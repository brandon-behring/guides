### 2.1 Transfer model — operationalized

v0.2 committed to transfer-over-retention. v0.3 operationalizes via two design moves:

**(a) Use PFL-style assessment in chapter exercises.**
Per `schwartz2005efficiency` (`ev_transfer_evaluation_methods_0001`): conventional sequestered problem-solving tests underestimate learners' Preparation for Future Learning. Chapter exercises should test *the ability to learn a new related concept* rather than only recall + apply the chapter's stated content.

Concrete pattern: each chapter ends with a "stretch problem" that introduces a *related but unseen* technique and asks the learner to reason about it using the chapter's tools. This costs ~10% of chapter length; pays off in transfer measurement.

**(b) Use productive failure for hard chapters.**
Per `kapur2008productive` (`ev_transfer_evaluation_methods_0002`): ill-structured problems *before* explicit instruction produce stronger transfer than well-structured-first sequencing — empirically validated in 11th-grade Newtonian kinematics; the effect should generalize to graduate-level statistics + ML.

Concrete pattern for the experimentation pilot guide: chapter 4 (hypothesis testing introduction) opens with a "what would you do?" framing of a real A/B test outcome, *before* presenting the formal machinery. Learner generates intuitions, then chapter unpacks why those intuitions are right/wrong.

**Pessimism note (`detterman1993transfer`, `barnett2002when`)**: far transfer remains empirically rare. v0.3 accepts that the guides should aspire to *near transfer within a domain* + *medium-transfer to adjacent technical roles* — NOT far transfer to unrelated domains. Reading-track design should respect this constraint.

### 2.2 Multi-paradigm presentation — UDL-grounded

v0.2 declared a `paradigms[]` frontmatter field. v0.3 specifies its semantics + UDL backing.

**Canonical paradigms** (extensible via per-guide additions):
- `visual` — diagrams, plots, animations, equations rendered visually
- `symbolic` — math notation, formulas
- `code` — runnable code blocks (Python, R, SQL primarily)
- `prose` — natural-language exposition
- `tabular` — structured tables, decision matrices
- `interactive` — embedded widgets (sliders, sandboxes — Phase 2+ via scaffold extensions)

Per `cast2018udl` (`ev_multi_paradigm_presentation_0001`): UDL's "multiple means of representation" principle requires that key concepts are accessible via ≥2 paradigms — not redundantly (which violates Mayer's redundancy principle, see below) but complementarily.

Per `mayer2014cambridge` (`ev_multi_paradigm_presentation_0003`): the 12 multimedia learning principles (coherence, redundancy, spatial + temporal contiguity, modality, multimedia, signaling, segmenting, pre-training, personalization, voice, image principles) constrain how paradigms combine. Notably:
- **Redundancy principle**: don't present the *same* info in prose AND on-screen text simultaneously
- **Modality principle**: prefer narration + visual over text + visual when both available
- **Signaling principle**: highlight structure (headings, callouts, arrows in figures)

Per `paivio1991dual` (`ev_multi_paradigm_presentation_0002`): dual-coding (verbal + nonverbal) representations strengthen retrieval — supports the combination of prose + symbolic + visual but **not** prose + on-screen text (same channel = redundancy violation).

**Frontmatter validation rule (v0.3 lock)**: chapters declare `paradigms: [visual, symbolic, code, prose]` as ordered list. Lint warns if `paradigms` contains <2 entries (fails UDL representation principle) OR if a paradigm is declared but absent from chapter body.

### 2.3 LLM-as-coach interface — risk-aware

v0.2 committed to an LLM-as-coach interface. v0.3 specifies design constraints driven by the `llm_as_coach_interfaces` dossier.

Per `vanlehn2011relative` (`ev_llm_as_coach_interfaces_0001`): ITS effect size d=0.76 ≈ human tutoring d=0.79. **LLM tutors should be expected to provide ITS-class benefits, not magical gains.**

Per `khan2024efficacy` (`ev_llm_as_coach_interfaces_0002`): Khanmigo's 2024 efficacy report shows significant learning gains across conditions but **no statistically significant differences between groups in one study**. Reading: LLM tutoring's marginal benefit over alternatives is empirically uncertain at scale.

**Design implications for v0.3:**
1. **No mastery claims based solely on LLM-tutor interaction.** Sycophancy + hallucination + illusion-of-competence are documented LLM-tutor failure modes; the coach interface should not signal "you understand this" without external evidence (capstone, peer review, real-world application).
2. **LLM-coach role is Socratic, not authoritative.** Interface should prompt learners to articulate reasoning, then present canonical answers — never substitute for the learner's own work.
3. **Coach must cite sources from the in-repo dossiers.** Specifically: LLM-coach responses about pedagogy should reference bibkeys from `~/guides/docs/research/<topic>/bib_ledger.yml`. Responses about content should reference bibkeys from the relevant per-guide `~/guides-<slug>/docs/research/<sub-topic>/bib_ledger.yml`. Hallucinated citations are a hard-fail.

**Implementation timeline (deferred)**: LLM-coach UI is not in Phase 1 pilot guide scope. Reserved as a Phase 2 commitment; v0.3 specifies the design constraints so Phase 2 implementation has a target.

### 2.4 Capstone + portfolio assessment

v0.2 deferred capstone work to Phase 1.5 (Q1 2027). v0.3 specifies capstone design backed by `capstone_portfolio_assessment` dossier.

Per `kuh2008high` (`ev_capstone_portfolio_assessment_0001`): capstones are 1 of 10 AAC&U high-impact educational practices; recommendation is that every learner participate in ≥2 high-impact activities. For the guides project, this maps to:

- **Per-guide capstone**: each guide should ship with a small capstone artifact (e.g., for experimentation: a runnable simulation comparing CUPED vs naive A/B test variance reduction on synthetic data).
- **Cross-guide portfolio**: learners completing multiple guides accumulate a portfolio of capstone artifacts. The portfolio itself becomes the demonstration of transfer (per §2.1).

**Phase 1.5 capstone for `experimentation` pilot**: defer specifics; will fold into the capstone build at that phase.
