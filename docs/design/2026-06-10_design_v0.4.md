## 2. Amendments

### 2.1 Positioning — company-agnostic, interview-prep-led (supersedes the Anthropic-arc emphasis)

The design lineage (v0.1–v0.3 via the interview-prep seed) carried an Anthropic-arc emphasis. Canonical positioning
is now: **a public, company-agnostic, interview-prep-led series on the AI-native dimensions of AI engineering**, for
engineers switching INTO AI-eng (SWE/DS background; foundations assumed/linked). **Success metric = public teaching
traction.** Company-agnostic means **core + how-to-localize**: industry-variation callouts (frontier labs · big tech ·
marketplaces · fintech · healthcare · enterprise), never per-company content. Per-company research stays private
input. Demand evidence (independent 94-source baseline, recorded blind) frames every guide's "what's tested / how
candidates fail"; the demand-spine strict-live synthesis stays descoped — per-chapter judgment over a blocking run.

### 2.2 Architecture — series-scoped repos (amends "per-guide repos")

v0.2/v0.3 locked a per-guide-repo pattern (`guides-<slug>`). Amended to **series-scoped repos**:

- A **series** of related guides lives in **one repo** as Astro content collections under `src/content/<guide>/`,
  with a `generateId` that namespaces chapter ids by guide folder → URLs `/chapters/<guide>/<slug>/`; slugs unique
  per guide, one shared `companion/` library, per-guide capstones. Proven in `guides-ai-engineering` (two guides
  coexisting; scaffold issue #132 carries the second-consumer evidence upstream; first-class multibook = #15,
  closed-deferred-post-v4.x upstream).
- **Standalone guides keep their own repos** (`guides-experimentation` unchanged). The hub remains landing +
  pedagogy + strategy; per-guide/series repos remain the content homes.
- Rationale: the 7-repo plan fragmented shared companions, cross-guide bridges, and the assessment spine; one series
  repo keeps "completeness over DRY" cheap and makes guide-to-guide links ordinary relative links.

### 2.3 Assessment spine — the 4-dimension rubric (new design element)

Every chapter in the series grades against the same independently-validated rubric: **Technical Correctness ·
Trade-off Awareness · Evaluation Rigor · Communication** (from `/ai-eng-sim`; independently corroborated by the
demand baseline — communication is the #1 documented rejection reason). Design requirements it imposes:
- a "How this is graded" rubric tie-in section per chapter;
- stable LOS ids with `anchor:` references, **bijective** with prose anchors (lint upstream: scaffold #130);
- capstones scored against the same four dimensions, making cross-guide portfolios comparable.

### 2.4 Chapter shape — promoted to design level (build-validated)

The shape specified at roadmap level (06-03 §5) shipped in 13 chapters and is now design-canonical:

`<YouWillLearn>` → **productive-failure opener** + `<Pitfall>` → principle + **worked-example fading**,
multi-paradigm-complementary (per §1's Mayer constraints) → **ICAP-scaffolded interactive demo** → interleaved
`<Practice>` + `<details>` solutions → **4-dim rubric tie-in** + industry-variation callout → **PFL stretch** →
provenance. Do-not-do list unchanged (learning-styles, far-transfer claims, rereading, passive interactivity,
over-scaffolding).

### 2.5 Companion libraries — build-your-own-X, triple-duty (new design element)

Each series ships deliberately-minimal, hand-rolled libraries the learner builds chapter-by-chapter (`mini_eval`,
`mini_rag`, `mini_agent`, …): stdlib-only, tested, labeled "for learning, not production", **always bridged to the
production tool** (eval-toolkit, RAGAS, LangChain/LlamaIndex). One artifact, three roles: companion package · engine
behind the demos (computes the frozen JSON) · the build-it-yourself learning spine. This is the series' identity:
*learn AI engineering by building a minimal version of each system, then bridge to production.*

### 2.6 Demo policy — static client-side only (new design element)

Public guides ship **frozen-/no-model** interactivity only: `dump → JSON → Preact island`, ICAP-wrapped
(predict → interact → explain; never passive). Computed demo data is generated offline by companion code
(deterministic, seeded); quiz-style demos use **hand-authored** JSON wherever live model outputs would otherwise be
fabricated — demo honesty is a review dimension (§2.7). Live-LLM interactivity is the personal simulator's job,
out of scope for public guides. Upstream demo kit: scaffold #103.

### 2.7 Quality gate — independent review before "complete" (new design element)

A guide is **complete** only after an independent multi-dimension review by a fresh agent (no authoring context):
**math/statistics · demo honesty · factual claims · pedagogy-shape conformance · island/MDX integrity** — findings
recorded in-repo (`docs/REVIEW_FINDINGS_<date>.md`), all fixes applied, LOS↔anchor bijection verified, build +
validate + companion tests green. Template: the Evaluation guide's 2026-06-08 review. This generalizes the
independent-first methodology from research inputs to shipped artifacts.
