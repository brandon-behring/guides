# Interactive learning interfaces (chat vs notebook vs structured exercise)

Sub-area `A4` of the Research Plan: LLM-as-coach interfaces for technical learning dossier. 4 entries.

## A4.1 Studying the Effect of AI Code Generators on Supporting Novice Learners in Introductory Programming

- **Studying the Effect of AI Code Generators on Supporting Novice Learners in Introductory Programming** — Kazemitabaar et al. (2023); *CHI 2023*. [evidence]
  - **Source:** https://doi.org/10.1145/3544548.3580919
  - **Code:** —
  - **Mechanism:** In a 69-learner study using the Coding Steps environment, access to a Codex-based generator raised code-authoring completion and scores without harming manual code-modification performance, and reduced frustration.
  - **Result:** Controlled interface study of AI-assisted authoring for novices, directly relevant to scaffolded coding-coach design.
  - **Status:** Unverified
  - **Evidence:** ev_llm_as_coach_interfaces_0012

## A4.2 CodeAid: Evaluating a Classroom Deployment of an LLM-based Programming Assistant that Balances Student and Educator Needs

- **CodeAid: Evaluating a Classroom Deployment of an LLM-based Programming Assistant that Balances Student and Educator Needs** — Kazemitabaar et al. (2024); *CHI 2024*. [interface]
  - **Source:** https://doi.org/10.1145/3613904.3642773
  - **Code:** —
  - **Mechanism:** CodeAid answers conceptual questions, generates pseudo-code with line-by-line explanations, and annotates incorrect code with fixes without revealing solutions; deployed to 700 students for 12 weeks with thematic analysis of 8,000 usages plus surveys and 22 interviews.
  - **Result:** Premier CHI study of LLM-tutor interface design balancing scaffolding against academic-integrity guardrails at scale.
  - **Status:** Unverified
  - **Evidence:** ev_llm_as_coach_interfaces_0010

## A4.3 CodeHelp: Using Large Language Models with Guardrails for Scalable Support in Programming Classes

- **CodeHelp: Using Large Language Models with Guardrails for Scalable Support in Programming Classes** — Liffiton et al. (2023); *Koli Calling 2023*. [interface]
  - **Source:** https://doi.org/10.1145/3631802.3631830
  - **Code:** —
  - **Mechanism:** An LLM-powered automated TA with guardrails that gives guidance and explanations without revealing solution code; every query is a one-shot request with no follow-up dialogue, well-received by students and cheap to deploy.
  - **Result:** Contrasts a one-shot guardrailed-query interface against free-form chat, illuminating a key UX design tradeoff.
  - **Status:** Unverified
  - **Evidence:** ev_llm_as_coach_interfaces_0011

## A4.4 Ruffle&Riley: Insights from Designing and Evaluating a Large Language Model-Based Conversational Tutoring System

- **Ruffle&Riley: Insights from Designing and Evaluating a Large Language Model-Based Conversational Tutoring System** — Schmucker et al. (2024); *AIED 2024*. [interface]
  - **Source:** https://arxiv.org/abs/2404.17460
  - **Code:** —
  - **Mechanism:** A conversational tutoring system using two LLM agents in a learning-by-teaching format following the ITS inner/outer-loop structure; two studies (N=200) found high engagement and understanding but no significant short-term learning gains over reading.
  - **Result:** Bridges classic ITS loop structure to LLM conversational-tutor interface design with a null-result cautionary finding.
  - **Status:** Unverified
  - **Evidence:** ev_llm_as_coach_interfaces_0013
